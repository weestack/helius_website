Kerne & Linux

Kernen ved det allerede. De fleste sikkerhedsprodukter spørger den bare pænt

Sikkerhed der kører i kernen, ikke ved siden af.

Problemet

Runtime-sikkerhed på Linux sælges typisk som en lukket agent, licenseret per host, kørende som root, og med kode du ikke må læse. Den ser det, leverandøren besluttede at instrumentere, den koster mere når du vokser, og når den overser noget, kan du ikke finde ud af hvorfor. Imens har kernen haft de rigtige primitiver i årevis.

Tilgangen

Jeg skriver instrumenteringen i stedet for at leje den. eBPF-programmer koblet på procesforløb og de syscalls der faktisk betyder noget, LSM- og kprobe-hooks der håndhæver frem for at observere, og filtrering inde i kernen, så de uinteressante 99% aldrig bliver til trafik eller en ingest-regning. Userspace-delen er Rust, fordi hukommelsessikkerhed betyder ekstra meget i en proces der kører privilegeret på hver eneste af dine hosts.

Det får du

  • eBPF-probes koblet på de proces- og syscall-events din trusselsmodel handler om
  • Rust-agent i userspace, bygget fra kilde i din egen pipeline, ingen leverandørbinær
  • Filtrering inde i kernen, så uinteressante events aldrig forlader den
  • Gennemgang af angrebsflade: hvad kører, hvad kan nås, hvad kan fjernes
  • Strukturerede events leveret til den telemetri-pipeline du allerede kører
  • Probe-kildekoden i dit eget repository, dokumenteret godt nok til at ændre

Eksempel

probes/src/exec.bpf.c

SEC("tp_btf/sched_process_exec")
int BPF_PROG(on_exec, struct task_struct *task,
             pid_t old_pid, struct linux_binprm *bprm)
{
    struct event *e;

    /* Filter in the kernel. An event dropped here costs nothing —
       no ring buffer slot, no userspace wakeup, no egress, no bill. */
    if (!should_report(task))
        return 0;

    e = bpf_ringbuf_reserve(&events, sizeof(*e), 0);
    if (!e)
        return 0;

    e->pid  = bpf_get_current_pid_tgid() >> 32;
    e->ppid = BPF_CORE_READ(task, real_parent, tgid);
    bpf_probe_read_kernel_str(&e->comm, sizeof(e->comm),
                              BPF_CORE_READ(bprm, filename));

    bpf_ringbuf_submit(e, 0);
    return 0;
}

agent/src/main.rs

// Userspace half. The probe above fills a ring buffer; this drains it.
// Rust rather than C because this process runs privileged on every host —
// a use-after-free here is a root-level use-after-free.
let mut bpf = EbpfLoader::new()
    .btf(Btf::from_sys_fs().ok().as_ref())
    .load(include_bytes_aligned!("../../target/bpfel-unknown-none/release/probes"))?;

let program: &mut BtfTracePoint = bpf.program_mut("on_exec").unwrap().try_into()?;
program.load("sched_process_exec", &Btf::from_sys_fs()?)?;
program.attach()?;

let mut events = RingBuf::try_from(bpf.take_map("EVENTS").unwrap())?;

while let Some(item) = events.next() {
    // Zero-copy read straight out of the ring buffer. The kernel already
    // dropped everything the filter did not want, so anything arriving here
    // is worth the cycles to parse.
    let e: &Event = unsafe { &*(item.as_ptr() as *const Event) };

    sink.emit(Record {
        pid: e.pid,
        ppid: e.ppid,
        comm: str::from_utf8(&e.comm)?.trim_end_matches('\0'),
        // Process trees, not a flat firehose: the parent is resolved here so
        // whoever reads this at 3am can see what actually spawned what.
        ancestry: tree.resolve(e.ppid),
    })?;
}
