Blackbox Linux

An eBPF-based runtime visibility agent for Linux servers, written in Rust. It watches process and syscall activity in the kernel, filters the noise early, and hands you structured events — without a proprietary binary running as root.

Blackbox Linux is not released yet. This page describes what the project aims to be, not what you can download today. First public release is targeted for December 2026.

Want to hear when it lands?My pledge

The problem

Runtime security on Linux is largely sold as closed agents licensed per host. You cannot read what they do, you cannot audit what they send, and the price scales with exactly the thing you were hoping to grow. The open alternatives exist but tend to assume you have a platform team to operate them. Meanwhile the kernel has had the right primitives for years.

The approach

Attach eBPF programs to the events that matter — process lifecycle, execution, and the syscalls that indicate something interesting — and do the filtering in the kernel before the data ever costs you anything. Group related events into process trees so a human can read them. Then ship them wherever you already send telemetry, in a format you did not have to buy a parser for.

What it does

Process-tree tracing

fork, execve and exit correlated into trees rather than a flat firehose of unrelated lines, so you can see what actually spawned what.

Early-drop filtering

Rules evaluated close to the kernel so uninteresting events are discarded before they become egress, storage, or an ingest bill.

Rule engine

Declarative predicates over event fields — equals, contains, prefix, suffix, and boolean combinations — kept deliberately small and fast.

Written in Rust

Userspace agent in Rust with the probes built on aya. Memory safety matters more than usual when the thing runs privileged on every host.

Ships where you already look

Structured events over a ring buffer, batched out to your existing pipeline instead of a vendor-specific endpoint.

Open source, not open core

One codebase, one feature set, permissively licensed. There is no enterprise tier holding the useful parts hostage.

The approach

Architecture

Five stages, kernel outward. Each one exists to make the next one cheaper.

  1. 01

    eBPF probes

    Attached to process lifecycle and selected syscalls

  2. 02

    In-kernel filters

    Drop uninteresting events before they leave the kernel

  3. 03

    Ring buffer

    Lock-free hand-off from kernel to userspace

  4. 04

    Classifier

    Correlates raw events into process trees

  5. 05

    Rule engine

    Declarative predicates decide what is worth reporting

  6. 06

    Exporters

    Batched structured output to your telemetry stack

Roadmap

Targeting a first public release in December 2026. It is being built in the open because that is the only way to make the audit claim credible — but until it is tagged, treat everything here as intent rather than documentation.

  1. NowCore probes, filtering and process-tree correlation in private testing
  2. December 2026First public release: repository, licence, documented rule format
  3. AfterPackaging for common distributions, exporter integrations, hardening guides
